# WEEK 6 — SCOPE FREEZE

## MEDIFIN — Case #01: Toy Kingdom Inc.

Week 6 freezes the MEDIFIN MVP scope so that the team can focus on **integration, testing, bug fixing, and stabilization** rather than adding major new features.

---

## 1. Frozen MVP Scope

The final MVP focuses on:

> **One complete playable financial counseling case — Case #01: Toy Kingdom Inc.**

The protected structure remains:

```text
13 Screens / 6 Phases

1. Client Intake & Investigation
2. Diagnosis
3. Treatment & Execution Planning
4. Consequence
5. Reassessment
6. Final Assessment
```

### Core Features Retained

- Financial evidence investigation
- Diagnostic Files and Follow-Up Questions
- Primary Diagnosis
- Treatment Strategy
- Execution Timing
- Stakeholder Priorities
- Simulated Consequences
- Reassessment
- Counselor Performance Score
- Financial Resilience
- Governance Stability
- Counselor Case Report and feedback

These features form the complete core learning flow:

> **Investigate → Diagnose → Treat → Execute → Observe → Reassess → Learn**

---

## 2. Week 6 Development Priority

From this point, development focuses on:

1. connecting the existing frontend, data, and game logic;
2. finalizing decision-to-outcome rules;
3. testing the complete core flow;
4. fixing Critical and Major bugs;
5. stabilizing the public playable build.

New features should only be added if they are necessary for the protected core flow.

---

## 3. Postponed / Out of Scope

The following features are not required for the current MVP:

- Additional financial cases
- Open-ended AI chatbot
- AI-generated scenarios
- Custom company financial uploads
- Multiplayer
- Real-time financial data
- Advanced animations and visual effects
- Large-scale personalization

These may be considered after Case #01 is fully playable and tested.

---

## 4. Known Limitations

The current MVP has several intentional limitations:

- Only **one complete case** is included.
- Financial and scenario data are predefined for educational purposes.
- Consequences are generated through **rule-based simulation**, not predictions of real company outcomes.
- Detailed decision-to-outcome rules are still being calibrated and tested.
- Controlled variation, if used, must remain small enough that it does not change the core financial interpretation of the case.

These limitations are accepted because the Week 6 objective is to deliver a **small, connected, explainable, and testable MVP**.

---

## 5. Scope Freeze Decision

The team will not expand the core product scope before the current Case #01 is fully integrated and tested.

The Week 6 priority is therefore:

> **Complete the Core Flow → Test → Fix → Stabilize**

rather than:

> **Add More Features → Add More Cases → Increase Complexity**
