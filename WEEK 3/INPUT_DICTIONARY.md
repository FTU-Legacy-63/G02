# INPUT_DICTIONARY.md

## Case #01 — Toy Kingdom Inc.

> **Educational financial simulation inspired by the historical Toys "R" Us case.**

---

## 1. Purpose

This file defines the **minimum information and state variables required for Case #01**.

Each item answers five questions:

> **What does it mean? · What is its unit/format? · Where does it come from? · Where is it used? · What does it affect?**

The purpose is not to collect as much data as possible.  
An input is included only when it supports a meaningful **diagnosis, decision, consequence, or final explanation**.

---

## 2. Data Classification

To avoid confusing historical facts with game-designed information, all inputs are classified into three types:

| Type | Meaning |
|---|---|
| **Historical** | Based on publicly available information from the real Toys "R" Us case |
| **Simulated** | Created or adapted by the team for Toy Kingdom Inc. and disclosed in `ASSUMPTIONS.md` |
| **Game State** | Generated by the player's choices during gameplay |

> **Important:** Toy Kingdom Inc., the Anderson family, Houndstooth Capital, the FY2026 timeline, and governance events are fictional elements created for educational simulation. They are not historical facts about Toys "R" Us.

## Key Terms

### Same-Store Sales (SSS)

**Same-Store Sales** measures sales growth or decline from stores that have operated long enough to be comparable across periods.

It helps distinguish:

> **performance of existing stores**  
> from  
> **changes caused by opening or closing stores**

---

### Secured Debt

**Secured debt** is borrowing backed by specific assets.

If the borrower cannot meet its obligations, secured creditors generally have stronger claims over those pledged assets than unsecured creditors.

---

### Leverage

**Leverage** refers to the use of debt financing relative to the company's earnings, assets, or equity.

High leverage does not automatically mean a company will fail, but it may reduce financial flexibility when operating conditions deteriorate.

These inputs provide context that may change how the player interprets the financial information or manages implementation risks.

| Field | Meaning | Unit / Format | Type / Source | Used in / Output affected |
|---|---|---|---|---|
| `investment_needs` | Major programs competing for limited capital: store renovation, digital, fulfillment, supply chain, customer experience and holiday inventory | list | Simulated from case context | HS-B → helps assess consequences of limited reinvestment capacity |

| `management_track_record` | Results of major initiatives implemented during previous periods | structured list | Simulated/adapted | HS-F → helps evaluate whether previous operational responses solved the underlying constraint |
| `holiday_liquidity_risk` | Potential pressure on liquidity if holiday performance is weaker than expected | scenario state · text | Simulated | HS-C / CH1-C → affects interpretation of liquidity and timing decisions |
| `governance_conflict` | Conflict among David, Michael and Richard over company strategy and control | categorical / text | **Simulated** | HS-G → affects governance-related decisions and consequences |

# 5. Investigation State

These variables record **what information the player has chosen to investigate**.

They are not financial facts about the company.

| Field | Meaning | Format | Source | Output affected |
|---|---|---|---|---|
| `selected_diagnostic_files` | The three files selected by the player on Screen 2 | array of HS codes | Game State | Determines which detailed evidence is available before diagnosis |
| `locked_diagnostic_files` | The four files not selected on Screen 2 | array of HS codes | Derived Game State | Prevents the player from accessing all information in one playthrough |
| `hs_g_opened` | Whether Governance & Family information has been verified | boolean | Derived from `selected_diagnostic_files` | Determines whether hidden governance information is confirmed |
| `selected_followup_questions` | Two supplemental questions selected on Screen 3 | array of CH1 codes | Game State | Provides limited additional information before full financial review |
| `selected_final_question` | Final diagnostic question selected on Screen 5 | CH2 code | Game State | Records which hypothesis the player chooses to investigate immediately before diagnosis |

### Why are some files locked?

The game intentionally limits information access to simulate **decision-making under incomplete information**.

The purpose is not to hide information randomly.

The player must decide:

> **Which information is important enough to investigate before making a professional judgment?**

# 6. Decision & Scenario State

These variables are generated by the player's decisions and are carried forward to later screens.

| Field | Meaning | Format | Source | Output affected |
|---|---|---|---|---|
| `selected_diagnosis` | Primary financial problem identified by the player | CD-A to CD-F | Game State | Determines the player's initial interpretation of the case |
| `selected_treatment` | Treatment strategy selected after diagnosis | PD-A to PD-F | Game State | Determines the main intervention used in the consequence stage |
| `selected_timing` | Timing selected for implementation | TG-A to TG-D | Game State | Changes implementation risk and later consequences |
| `stakeholder_priorities` | Three stakeholder groups prioritized before implementation | array of 3 categories | Game State | Changes supplier, creditor, employee, customer and governance consequences |
| `credibility` | Degree to which the player's decisions are supported by available evidence | Low / Medium / High | Derived Game State | Affects whether certain complex treatments can be approved and how final decision quality is described |
| `financial_resilience` | Resulting financial condition of Toy Kingdom after player decisions | Stable / Fragile / Collapse | Derived Game State | One dimension of the final outcome |
| `governance_stability` | Resulting stability of company control and family governance | Stable / Divided / Loss of Control | Derived Game State | Second dimension of the final outcome |
| `revised_diagnosis` | Diagnosis after new information becomes available | CD-A to CD-F | Game State | Records whether the player updates the original judgment |
| `revised_treatment` | Treatment after reassessment | PD-A to PD-F | Game State | Determines the final treatment path after reassessment |

# 7. Main Output Supported by These Inputs

The information above ultimately supports the **Counselor Case Report**.

The report summarizes:

- information investigated;
- diagnosis;
- treatment;
- implementation timing;
- stakeholder priorities;
- reassessment;
- Financial Resilience;
- Governance Stability; and
- Credibility.

The purpose of the output is not only to show whether the company survives.

It should make the player's **financial reasoning and decision path visible**.

# 8. Information Readiness Rules

A field is considered **ready for use in the MVP** only when the team can answer:

1. **What does this field mean?**
2. **Where does it come from?**
3. **Where is it used in the product?**
4. **What decision, consequence, or explanation does it affect?**

Additional rules:

- Every **historical field** must map to `SOURCE_USE_MAP.md`.
- Every **simulated or fictional field** must be disclosed in `ASSUMPTIONS.md`.
- Every **Game State** must correspond to an actual player choice or resulting scenario state.
- If a field does not affect information available, a decision, a consequence, or the final explanation, it should be removed from the MVP.
- Formulas, scoring weights, thresholds, and detailed state-transition rules are specified separately in the **Week 4 logic evidence**, not in this Week 3 Input Dictionary.
